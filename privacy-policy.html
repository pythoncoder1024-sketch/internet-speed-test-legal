Privacy Policy — Internet Speed Test

Last updated: October 28, 2026

This Privacy Policy describes how the standalone Android application Internet Speed Test (package name net.toolslibrary.internetspeedtest) handles information. The app is published by ToolsLibrary.

Privacy contact: support@toolslibrary.net

1. Scope

This policy covers only the standalone Internet Speed Test Android app. It does not cover the ToolsLibrary multi-tool Android app (net.toolslibrary.app), the ToolsLibrary website at toolslibrary.net, or other ToolsLibrary products, which have their own notices where applicable.

2. What the app does

Internet Speed Test measures an approximate connection speed between your device and the ToolsLibrary-owned test server at https://toolslibrary.net by running ping, download, and upload measurements when you start a test.

Results are approximate. They are not laboratory measurements or guaranteed ISP line rates.

3. Information processed during a speed test

When you run a test, the app makes HTTPS requests to ToolsLibrary endpoints:

  • GET https://toolslibrary.net/__down?bytes=N (latency samples and download measurement)
  • POST https://toolslibrary.net/__up (upload measurement using generated binary test data)

The upload body is generated on the device for measurement purposes. It is not your personal files, photos, messages, or documents.

Like any HTTPS connection to a server, the ToolsLibrary test server can see standard connection metadata necessary to deliver the response, which typically includes your device’s public IP address, approximate timing/size of the transfer, and ordinary HTTP request metadata. ToolsLibrary operates these endpoints to provide the speed test.

Based on the current server design described for these probes, the upload body is not retained as a long-term content store for the test payload.

4. What stays on your device

Speed-test results can be saved in a local history database on the device. The app can also store an internet-plan note, a test-spot name, and a schedule for later tests on the device. This history is not uploaded to a ToolsLibrary account. There is no sign-in and no cloud sync of that history.

You can choose to share a completed result through Android’s share sheet. That send is started by you and goes to the app you pick.

Network type classification (for example Wi‑Fi vs cellular) uses Android ConnectivityManager / NetworkCapabilities on the device. The app does not request location permission for this. A Wi‑Fi name is stored with a result only when Android itself returns one. On most devices that name is redacted unless the system already allows it.

5. Permissions

The app requests:

  • INTERNET — required to contact the ToolsLibrary test server and to load an advertisement when one is allowed
  • ACCESS_NETWORK_STATE — to detect connectivity / network type on the device
  • POST_NOTIFICATIONS — to show a notification for a test you scheduled, after you allow notifications

The Google Mobile Ads SDK also declares AD_ID (com.google.android.gms.permission.AD_ID) so it can read the Android advertising ID when ads are requested. The app does not declare location, contacts, phone-state, camera, microphone, photos, or file permissions for the speed test.

6. Advertising, analytics, and third-party SDKs

Release builds can show one Google AdMob banner on the home screen when the screen is idle or showing a completed result. The banner is removed while a speed test, stability test, or LAN scan is running. The app does not show interstitial, native, or rewarded ads.

Before requesting an ad, the app uses Google’s User Messaging Platform (UMP) SDK. On launch it refreshes consent information and, where Google’s Privacy & messaging configuration requires it, shows a consent form. If that SDK reports that ads must not be requested, the app does not request one. Where a privacy-options entry is required, Support and About offer Ad privacy options. UMP stores the consent choice on the device. The UMP SDK does not use the advertising ID.

When an ad is requested, the Google Mobile Ads SDK can collect and share, for advertising, measurement, and fraud prevention: the device IP address (which can be used to estimate a general location), ad and app interactions such as a tap on an ad, diagnostic information about the SDK, and device or account identifiers including the Android advertising ID and app set ID. You can reset or delete the advertising ID in Android settings. Google describes this collection in its Mobile Ads SDK Play data disclosure. Ad requests use HTTPS.

The app does not integrate Firebase, Google Analytics, or a crash-reporting SDK. Speed measurements are not sent to Ookla, Fast.com, or M-Lab client libraries. Networking for the speed test uses the open-source OkHttp client library to communicate with https://toolslibrary.net.

If you install the app from Google Play, Google Play and Android system services may process installation and update data under Google’s policies. That is separate from ToolsLibrary’s speed-test measurement traffic.

7. Accounts and personal information

The current app does not provide a ToolsLibrary user account, sign-in, profile, or payment flow inside the app. It does not ask you to enter your name, email, or other identity details to run a speed test.

8. Children

Internet Speed Test is a general-audience utility and is not directed at children. A device that uses the app may still request an advertisement as described in section 6. The app does not ask children to create an account or to enter their name or email.

9. Security

Speed-test traffic uses HTTPS. No method of transmission is completely secure. Use official app stores and keep your device updated.

10. Changes

We may update this policy as the product evolves. The “Last updated” date at the top of this page will change when we do.
